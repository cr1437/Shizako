## 描述（Body）

```markdown
Shizako is an Apache-2.0 fork of Shizuku (github.com/RikkaApps/Shizuku) with an
extra UI and tooling. Submitting the dedicated F-Droid build variant.

**Source / metadata**
- Repo: https://github.com/cr1437/Shizako (official repo of the author)
- Builds from tag `zako3.13`, versionCode **313** (monotonically increasing per release)
- versionName `zako3.13-f` (`-f` suffix marks the F-Droid variant; the GitHub
  release `zako3.13` is the full-feature build from the same source)
- License: Apache-2.0, LICENSE + NOTICE included

**F-Droid-specific build (`gradle: :manager:assembleRelease -Pfdroid`)**
- The `-Pfdroid` property toggles everything in one place:
  - in-app updater & update checks **fully disabled** (self-update can never
    work with F-Droid's signatures) — no update UI is shown at all
  - "one-click inject" (downloading/installing third-party APKs) hidden
  - AI explain feature (proprietary provider endpoints) removed → **no
    NonFreeNet AntiFeature needed**
  - third-party GitHub mirrors removed from update checks (official
    api.github.com only)
  - CN mirrors (maven.aliyun.com) in `settings.gradle` automatically disabled →
    only google() / mavenCentral() / gradlePluginPortal() are used
- All binaries are built from source during the build:
  - `shizako-stub.apk` was previously committed as a binary — removed from the
    repo; it is now generated by the `:stub` module at build time
  - `rish_shizuku.dex` is generated by the `:shell` module at build time
    (never committed)

**Other**
- NDK 29.0.14206865 (declared in the recipe and root build.gradle)
- No ads, no analytics, no tracking (DAU feature was removed), no
  Firebase/Google Play services
- Note: the app intentionally declares the official Shizuku provider authority,
  so it cannot be installed alongside the official Shizuku app. This is a
  deliberate, documented design of this fork (see README), and the app uses its
  own app id / permission names as required by the upstream license (NOTICE).
```

## 提交步骤

1. <https://gitlab.com> 登录 → fork <https://gitlab.com/fdroid/fdroiddata>
2. 把 `com.churan.shizako.yml`（同目录）复制到 fork 的
   `metadata/com.churan.shizako.yml`，提交到新分支（如 `com.churan.shizako`）
3. 新建 Merge Request，标题与描述用上面的文案
4. 过一遍 fdroiddata MR 模板的自查清单（重点：License、AntiFeatures=无、
   预编译二进制=无、tag 与 versionCode 对应）

## MR 时可能被追问的两项（见 README.md 第 4 节）

1. **libsu 依赖只在 jitpack.io**（Maven Central 无）→ 若他们的构建机不放行
   jitpack，需要改为 srclibs 源码构建或替换依赖
2. **UpdateCheckData 的 versionName 不带 `-f` 后缀** → 以 versionCode 313 为准；
   若 linter 报告不一致，把 `-f` 后缀下沉进根 build.gradle 的 versionName
