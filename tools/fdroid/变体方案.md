# F-Droid 变体实施方案（单项目 + 分文件夹）

决策：**一个项目、两个变体**，变体专属代码各在自己的文件夹里；不做两份项目副本
（两份会各自漂移，改一个 bug 要改两遍）。

## 一、目录结构（变体代码分开放）

```
Shizako-KernelSU-UI/
├── manager/src/main/        ← 两个变体共用
├── manager/src/main/java/moe/shizuku/manager/fdroid/
│                            ← 【F-Droid 专属】此文件夹内只放变体开关与替代实现
└── tools/fdroid/            ← F-Droid 的 recipe、合规文档、本方案
```

产物命名也分开（都靠构建参数控制，仓库里不产生第二份源码）：

```
shizako-zako3.12-release.apk      ← GitHub 版
shizako-zako3.12-f-release.apk    ← F-Droid 版（版本名带 -f 后缀）
```

## 二、构建开关（改动最小、不动现有产物路径）

在 `manager/build.gradle` 的 `defaultConfig` 里加：

```groovy
def fdroidBuild = project.hasProperty('fdroid')
// 版本名带 -f 后缀（F-Droid 版与 GitHub 版一眼可分）
versionName rootProject.ext.versionName + (fdroidBuild ? '-f' : '')
// 编译期开关，供代码里判断
buildConfigField "boolean", "FDROID_BUILD", "${fdroidBuild}"
```

构建命令：

```bash
./gradlew :manager:assembleRelease              # GitHub 版（zako3.12）
./gradlew :manager:assembleRelease -Pfdroid     # F-Droid 版（zako3.12-f）
```

> 为什么不用 productFlavors：flavor 会把产物路径改成 `apk/<flavor>/release/`，
> 影响现有发版脚本与官网下载链接；用构建属性可以达到同样效果且**不动现有路径**。

## 三、需要在 F-Droid 版关掉的三件事

统一在 `manager/src/main/java/moe/shizuku/manager/fdroid/FdroidBuild.kt` 里集中判断，
业务代码只引用它，避免 `BuildConfig.FDROID_BUILD` 散落各处：

```kotlin
package moe.shizuku.manager.fdroid

import moe.shizuku.manager.BuildConfig

/** F-Droid 变体开关：集中一处，便于审查，也便于以后调整。 */
object FdroidBuild {
    /** 是否 F-Droid 版（版本名带 -f 后缀的那个） */
    val isFdroid: Boolean get() = BuildConfig.FDROID_BUILD
    /** 自动更新与「下载并安装 APK」——F-Droid 严禁自更新（签名不同，必然失败） */
    val allowSelfUpdate: Boolean get() = !isFdroid
    /** 一键注入（会下载并安装第三方应用 APK）——F-Droid 政策不允许 */
    val allowOneClickInject: Boolean get() = !isFdroid
    /** AI 解释（内置多家专有服务商入口）——关掉即可不带 NonFreeNet 反特性 */
    val allowAiExplain: Boolean get() = !isFdroid
    /** 更新检查用的第三方 GitHub 反代——同样属 NonFreeNet 边缘，一并关掉 */
    val allowUpdateMirrors: Boolean get() = !isFdroid
}
```

各开关的落点：

| 开关 | 具体位置 | 改法 |
|---|---|---|
| `allowSelfUpdate` | `MainActivity.onResume` 里的 `UpdateChecker.checkOnAppForeground`；`AutoUpdateScheduler.schedule`；设置页的「检查更新」入口 | 用 `if (FdroidBuild.allowSelfUpdate)` 包住；F-Droid 版完全不显示更新入口 |
| `allowUpdateMirrors` | `UpdateChecker.API_ENDPOINTS` | F-Droid 版只用官方 `api.github.com`，不走反代 |
| `allowOneClickInject` | `RecommendedApps` / `AppsDownloadFragment` / `UpdateChecker.downloadFromUrl` 的调用点 | F-Droid 版隐藏「一键注入」与推荐应用下载入口 |
| `allowAiExplain` | `ComputPage` / `AiExplainUtil` 的入口与设置项 | F-Droid 版隐藏 AI 解释按钮与 API Key 设置项 |
