授权

官方生态直连

设备所有者

COMPATIBILITY

生态兼容

通信协议与上游 Shizuku 同一套 —— 但名字、包名、身份都是她自己的。

API

Shizuku-API 应用零改动直连

官方 dev.rikka.shizuku:api 写的应用（MT 管理器、冰箱、SystemUI Tuner 等）装好就能连：服务端只校验「是否请求了权限」，首次连接照样弹授权框。

设备所有者

自己的设备所有者

被设为 Device Owner 后，Dhizuku-API 应用把 Shizako 当 Dhizuku 用；特权转发全部在 Shizako 进程内完成，不给第三方开系统 binder 后门。

共存

可与官方 Shizuku 共存

自己的包名、自己的权限名、自己的 provider authority —— 两者可以同时安装，哪个在跑就用哪个。

为什么

为什么包名不一样

按上游许可要求，fork 不得使用上游的应用 ID、名称与 moe.shizuku.manager.permission.*，所以本项目用 com.churan.shizako 和自己的一套权限名。

TRUST

怎么确认你装的是官方构建

所有官方构建都用同一张证书签名。指纹对不上 = 这份 APK 被人重打包并换过签名，不要安装、不要授权。

FAQ

常见问题

要 Root 吗？

不需要。无线调试或 USB 就能激活；有 Root 也可以，只是姿势更多。

跟 Shizuku 是什么关系？

兼容 Shizuku-API 生态 —— 用官方 SDK 写的应用零改动直连。按上游许可要求使用自己的包名与权限名，因此可以和官方版本装在同一台设备上。

授权给应用安全吗？

每个应用都要你亲自点头才拿得到通行证，白名单本地记录、随时收回；Dhizuku 特权转发只在 Shizako 进程内完成，存储代理还要额外单独授权并逐次审计。

支持哪些系统？

Android 7.0 及以上；无线调试激活需要 Android 11+。

会收集我的数据吗？

不收集。应用不上报任何使用数据；自动检查更新只请求 GitHub 的公开 release 接口，用来判断有没有新版本。

开源吗？我能自己编译吗？

开源，Apache-2.0。克隆仓库后执行 ./gradlew :manager:assembleRelease 即可，需要 JDK 21 与 Android SDK 36。
